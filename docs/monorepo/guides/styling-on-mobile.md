# Styling on mobile: DESIGN.md, rule by rule

`DESIGN.md` records the world as built on the web. This guide says how each
of its rules is followed in React Native, and names what cannot be carried
so it is a recorded ceiling rather than a quiet loss. Read the section of
`DESIGN.md` first; the tables here assume it.

The one principle: **the phone follows the rules, not the stylesheet.**
A rule that says *the figure is flatter than the title* is followed with
the fonts the platform has. A rule that says *three carriers, always* is
followed exactly.

## Units

The web sets everything in `rem` at a 16px root. The phone uses density
independent pixels; `@didactic/tokens` carries both.

| Token | rem | px on the phone |
| --- | --- | --- |
| `step--2` | 0.6875 | 11 |
| `step--1` | 0.8125 | 13 |
| `step-0` | 0.9375 | 15 |
| `step-1` | 1.25 | 20 |
| `step-2` | 1.75 | 28 |
| `step-3` | 2.5 | 40 |
| `step-4` | clamp(3rem, 6vw, 5rem) | 48 (the clamp's floor; 6vw of a phone is under it) |
| `space-1` … `space-6` | 0.25 · 0.5 · 0.875 · 1.375 · 2.25 · 3.5 | 4 · 8 · 14 · 22 · 36 · 56 |
| `foot-bar` | 3.75 + inset | 60 + `insets.bottom` |

Tracking is stated in `em` on the web; on the phone `letterSpacing` is in
px, so multiply by the size: `0.1em` at 11px is `1.1`; `0.14em` at 11px
is `1.54`; `-0.02em` at 40px is `-0.8`. Line heights are ratios on the
web and px on the phone: `0.95` at 40px is `38`.

## §1 Ground and materials

| Rule | On the phone |
| --- | --- |
| Paper, inks, plates, rules as hex | `tokens.colour.*`, verbatim. The agreement test keeps them equal to the CSS. |
| Light only, no dark mode | `userInterfaceStyle: "light"` in `app.json`. Never read `useColorScheme`. |
| The sheet on the press bed | A phone shows no bed around a sheet; the sheet is the screen, paper edge to edge, with the band bleeding to the edges. The `--press-bed` colour appears only behind the graph's bottom sheet and as the ground under a docked panel. |
| Paper tooth as two gradient threads | RN has no repeating gradient. A 3×4 px PNG tile carrying both threads at the sheet's alphas (`0.04` / `0.03`) under `ImageBackground resizeMode="repeat"`, generated by `scripts/tooth.mjs` from the token values. It must read as threads on a real screen; if it reads as noise, drop it rather than coarsen it. |
| The graph's 48px drill grid | Drawn in Skia from the same constants. |
| Reversed-out text is paper at alpha | `rgba(239,231,214,a)` with `a` from `tokens.reversed`. Never a lighter green. |

## §2 Type

Fraunces and Archivo load through `expo-font` from `@expo-google-fonts/*`.

**The ceiling, and where it lifts.** React Native cannot set
`font-variation-settings`, so on the native sheets the `SOFT`, `WONK` and
`opsz` axes that carry the web's role system are not available. Google
Fonts ships Fraunces as static instances at three optical sizes, and those
are what the native sheets use. `SOFT` and `WONK` are lost there; this is
recorded in `PARITY.md` and is not to be faked by tracking or weight.
Inside the reader (§8) the lesson body is a browser engine with the
variable font inlined, so prose headings keep every axis the web gives
them. The band above the reader is native and does not; the two sit a
rule apart and are set from the same family, which is as close as the
platform allows.

| Web role | Web setting | Phone face | Size |
| --- | --- | --- | --- |
| Home masthead | `SOFT 40, WONK 1, opsz 120` | `Fraunces_144pt_600SemiBold` | 48 |
| Surface title | `SOFT 40, WONK 1, opsz 72` | `Fraunces_72pt_600SemiBold` | 40 |
| Prose h1 | `opsz 60` | `Fraunces_72pt_600SemiBold` | 40 |
| Section / panel title | `opsz 40` | `Fraunces_72pt_600SemiBold` | 28 |
| Recommendation name | `opsz 36` | `Fraunces_72pt_600SemiBold` | 28 |
| Entry title | `SOFT 25, WONK 1, opsz 24` | `Fraunces_9pt_600SemiBold` | 20 |
| Strapline | `SOFT 20, WONK 0` | `Fraunces_9pt_400Regular` | 20 |
| Viability figure | `SOFT 10, WONK 0, opsz 30` | `Fraunces_9pt_600SemiBold` | 28 |
| Body, labels, controls | Archivo | `Archivo_400Regular`, `Archivo_600SemiBold`, `Archivo_700Bold` | as the ramp |

The rule *the figure is flatter than the title* survives: the figure takes
the sturdier 9pt cut at 28px while a section title of the same size takes
the 72pt cut. If the 9pt cut reads heavy for an entry title at 20px on a
device, move entry titles to 72pt and record it here.

`tabular-nums` globally: `fontVariant: ['tabular-nums']` on the base
`Text`; figures add `'lining-nums'`. `text-wrap: balance` has no
equivalent; titles wrap as they fall.

The label register is one style object in `apps/mobile/lib/theme.ts`:
`{ fontFamily: Archivo_400Regular, fontSize: 11, letterSpacing: 1.1,
textTransform: 'uppercase', color: ink.faint }` with the tracking swapped
for `0.66` (0.06em) or `1.54` (0.14em) by loudness.

## §3 Space

`tokens.space[n].px`, unmodified. `space-5` (36) is the band's block
padding and the sheet's horizontal padding; `space-4` (22) below 48rem,
which on a phone is always. `space-6` (56) at the foot of every sheet,
before the bar.

## §4 Construction

| Rule | On the phone |
| --- | --- |
| The masthead band | `components/Masthead.tsx`: plate ground, `space-5` padding, the running head inside it, the filed-under line, the title, then a `5` high mustard rule. |
| Curriculum takes ultramarine; topic takes its subject's ink | The band's `colour` prop; the same two exceptions, no others. |
| The filed-under line is a breadcrumb or it is not printed | Same component prop: `parents?: Array<{ label, href }>`; `undefined` prints nothing. |
| `border-radius: 0` everywhere | `borderRadius: 0` on every `View`, `TextInput` and `Pressable`. Android's default ripple is round; use `android_ripple={{ borderless: false, radius: 0 }}` or a plain opacity change. |
| Rules by weight | `borderBottomWidth: 1` in `rule`; `borderStyle: 'dotted'` for leader dots and the mobile figure divider; `2` in `rule.strong` for section heads; `2` in mustard for an action's underline; `5` for the head rule. |
| An action is a link with a mustard underline, not a button shape | A `Pressable` wrapping `Text` with `borderBottomWidth: 2, borderBottomColor: mustard`. Filled buttons only where the action commits: green ground, paper text, square, pressing to terracotta. |
| The fixed tree | Same `buildTopicTree` + `orderSubjectOutline` from `core`; nesting drawn with a `1` wide `rule` down the branch and a `space-3` tick out to each entry, as views. |
| The spread | Always one column; the margin's `2` top rule in `rule.strong` when stacked. |
| The measure | Not applicable: the sheet is the screen's width. |

## §5 Encoding state

Every rule in this section is followed exactly, because they exist for a
dim phone screen outdoors.

| Rule | On the phone |
| --- | --- |
| Viability printed as a number; *about*, italic, dimmed, and the caveat sentence under 0.4 confidence | `viabilityFigure` and the confidence threshold from `core`; `fontStyle: 'italic'`, `opacity: 0.62`, the caveat with its `2` wide mustard left rule. |
| Condition bar: hatch density, state word, `aria-label` | `StockBar` in `react-native-svg` from `core/stock`'s hatch table; the word from `STOCK_LABEL`; `accessibilityLabel` with the same sentence. `unsown` renders as outline only. |
| Holding size drives row weight | Dropped on the phone as the web drops it below 40rem: plate `48`, padding `space-4`. |
| Roots gauge grows | `RootsSpecimen` from `core/specimens` geometry; stem and taproot drawn with `strokeDasharray` / `strokeDashoffset` under Reanimated; `accessibilityValue={{ text: "3, Seedling" }}` on the slider. |
| Two figures compared | Two plates, same size, subject ink; verdict from `readVerdict`, never asked for. |
| Held / missing ground marked, not coloured | `2` solid green rule before held; `2` dotted terracotta before missing. |
| Emblems reversed, not drawn; must read at 48px | The silhouette path from `core/specimens` filled in paper on a `60×60` plate field. |
| Route chip carries the word | `ROUTE_LABEL` in the label register; the tick and colour redundant. |

## §6 The graph

Skia canvas, graphology, ForceAtlas2 with the constants from `core/graph`
(settle 400 iterations before first paint at `gravity 1.2, scalingRatio
24, slowDown 14`; run at `0.05, 80, 40`). Size, fade toward paper, hue,
edge ink, dormant label ink and the label flip all come from `core/graph`.
Pinch and pan through gesture-handler; a held seed is fixed for the drag.
The panel is a bottom sheet at 72% height, as the web's is below 40rem.

## §7 Motion

Reanimated with the three durations and two curves from `tokens.motion`
and `tokens.ease` (`Easing.bezier(0.16, 1, 0.3, 1)`). Travel is
`2.2 × 0.375rem` = `13.2` for a sheet arriving and `-8.8` for its band.
Staggered rows carry their index and lean on the same curve. No
reduced-motion guard, by the same decision as the web; the block that
would restore it lives in `lib/theme.ts` as a comment, as it does in
`globals.css`.

## §8 Reading and marking

The whole section is followed by not re-implementing it. The lesson body,
the refresher body and the note reader on the marked sheet are
`@didactic/reader`, the web's own `Prose`, `Highlighter`, `paintMarks`,
blocks, `Contents` and `NoteEditor`, bundled into one HTML file and loaded
into a `react-native-webview`. Every rule in §8 is therefore true on the
phone because it is the same code, including the touch rules (*nothing
opens on its own under a finger*, the offer floated beside the selection,
the docked panel), which were written for a phone browser in the first
place.

What the native side owns around it:

| Part | On the phone |
| --- | --- |
| The band and the filed-under line | Native `Masthead`, fixed above the reader as a header. |
| Scroll | The reader's. The band does not scroll with the prose; it is the sheet's head, held. |
| The foot | The reader's view ends at the foot bar; *complete this lesson at a depth* is a native control in a strip above the bar, so it is reachable without scrolling to the end. |
| Marks in and out | The message protocol in `packages/reader/embed/protocol.ts`; saving through `@didactic/api`; the reader is sent the new mark list after every save. |
| The note editor's keyboard | `KeyboardAvoidingView` around the WebView; the docked panel inside the reader rises with it. |
| Links out | The reader posts `open { href }`; the native side opens `expo-web-browser`. |
| Fonts | Fraunces variable and Archivo inlined in the bundle as data URIs, so the reader is never waiting on a network for the face it is set in. |
| The tooth | The reader's own CSS, as on the web. |
| The galley | Native, in the prose shape, shown until the reader posts its first `height`. |

**Rule — the reader is one implementation.** A fix to marks, blocks or
the note editor is made in `packages/reader` and reaches both platforms.
Nothing in `apps/mobile` draws prose.

## §9 Browser surfaces

`selectionColor` on every `TextInput` is mustard. Focus rings do not apply
to touch. Scroll indicators stay the platform's.

## §10 Responsive

The phone is always below every breakpoint. Everything `DESIGN.md` says
happens at `40rem` is the phone's only state: rows are cards, leader dots
are dropped, the graph panel is a bottom sheet, one-column contents,
docked panels. Tablets are not designed for in this pass; the phone layout
runs full width on them and that is recorded as a ceiling.

## What to do when a rule cannot be followed

Say so in `PARITY.md` with `partial` or `n/a` and the reason, and add a
row to this guide. Do not approximate a rule silently: a half-followed
rule is what turns a system into taste.
