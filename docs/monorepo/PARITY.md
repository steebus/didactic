# Parity record

The one place that says where every feature stands on each platform. A
feature is not finished until its row here is right, and a row is changed
in the same commit as the code that changes it.

**Mobile runtime:** not yet scaffolded. When Phase 4 lands, record the Expo
SDK and React Native versions here.

**Shared packages, as at 2026-09-12:** `@didactic/core` (35 modules — 33,
plus `fsrs` and `clozes`) and
`@didactic/tokens` exist and are read by `apps/web`. The *Shared via*
column below names where a row's logic will live; for rows whose module
has shipped, it now names something real rather than something planned.

## Status words

| Word | Meaning |
| --- | --- |
| `built` | Shipped and working on that platform. |
| `partial` | Shipped with a stated gap. The gap is in the Notes column, not implied. |
| `planned (n)` | Not built; scheduled for Phase *n* of `PLAN.md`. |
| `n/a` | Deliberately absent on that platform, with the reason in Notes. |

The *Shared via* column names the package module that both platforms read,
or `—` when a row is rendering only.

| Mathematics in a lesson | built | planned (5) | `lib/maths` (web), `core/clozes.mathSpans`; the phone reads the same rendered HTML | TeX between `$` and `$$` is typeset by KaTeX at render time. **MathML, not KaTeX's HTML**, and the reason is the allowlist: KaTeX's default output is a tree of spans carrying inline styles, and admitting it would have meant admitting `style` on every element in the prose — exactly the hole `markdown.ts` exists to refuse. The MathML tags are only ever mathematics; they carry no URL, no script and no ink, so the sanitiser widens by a bounded set that a model cannot reach through, and no stylesheet or font files ship at all. The tag and attribute lists are measured off KaTeX's own output over the notation a lesson actually uses — powers, fractions, roots, sums, limits, matrices, cases, accents, braces — rather than remembered, because a guessed list is a formula silently gutted into the text inside it. `mathcolor` and `mathbackground` are deliberately omitted. KaTeX is given no `trust`, so `\href`, `\url` and `\includegraphics` are refused at the source as well. Tokenised as a `marked` extension rather than as a pass over the string, which is what keeps a `$` inside a code fence a `$` — the same reasoning that resolves `lesson:` in a renderer. A formula KaTeX refuses prints verbatim, delimiters and all: a hole where an equation should be teaches less than the equation as typed. The block rule refuses a `$` inside a formula, because a lazy rule satisfies itself by swallowing a run of three display equations jammed onto one line into one formula that then fails — which is how a whole line came to print as raw TeX. Both painters walk the set formula and skip only its `<annotation>` — that carries the TeX it was set from and is rendered nowhere, so walking it would splice the source through the text a passage is searched for. A stored passage is looked for twice: as stored, then with its notation typeset. An agent's cloze quotes the lesson *source*, where an equation is still `$2^x = 100$`, while the page holds it *set*, where it reads as its glyphs — searched only as stored it was never found and the plum was never drawn. The second reading is produced by typesetting each formula in the quote and reading the text back off the result, so it is exactly what the page holds rather than an approximation of it. Block fields and the cloze card render through `renderInline` on a much shorter allowlist — emphasis, code and mathematics, no headings, lists or links. A blank may take a whole formula or none of one (`clozeProblem`, enforced on the reader's own clozes and the agent's alike from the same function): the card draws the passage in three pieces and typesets each, so a blank cutting through an equation would leave two halves that can only print as the raw TeX they have become. |

| How closely a bed follows the document it grew from | built | planned (5) | `core/documents.FIDELITY_RUNGS`, `core/documentBed` | Three rungs under any PDF filed as proof, and not a slider: each is a different path through the code, so a scale would promise an interpolation that does not exist. *To the letter* does not ask the model what the topics are — it tells it, one per chapter in the document's order, and asks only what each is called; the resolver still names each concept, because a topic is shared across every subject it sits under and "Getting started" is not something anyone can know. | Spaced repetition: the FSRS scheduler | built | planned (5) | `core/fsrs` | FSRS-5, the nineteen-weight version, pure and in `packages/core` with 26 tests — so the phone schedules a card exactly as the web does rather than to its own taste, and so the sheet can ask what an answer would cost *before* it is pressed. Nothing in it reads a clock: the caller says what `now` is, which makes every case a fixed sum rather than something that has to be waited for. Two numbers per card, stability (how long the memory lasts, in days) and difficulty (1–10), and a power-law forgetting curve rather than the exponential the older schedulers use — measured, memory has a far longer tail, which is why an exponential keeps asking for things the reader plainly still holds.
